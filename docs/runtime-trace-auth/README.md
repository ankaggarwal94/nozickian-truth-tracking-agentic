# Runtime trace authentication

Formal runtime claims require more than a transcript that says an agent was called. The package expects authenticated Claude Code stream events with native tool-use and tool-result boundaries for the required `ntt-*` lanes.

Authentication also requires exactly one canonical Claude SDK ResultMessage: `type: "result"`, `subtype: "success"`, `is_error: false`, an empty `permission_denials` array, and a nonempty canonical `result` payload. It must occur after every required lane result and be the final stream record. The official control fields are checked directly: `api_error_status`, `deferred_tool_use`, and (for this non-structured harness) `structured_output` must be null or absent; a present non-null `terminal_reason` must be exactly `completed`; and a present non-null `stop_reason` must be exactly `end_turn`. Missing, duplicate, premature, error-subtype, system-error, aliased, permission-denied, camel/hyphen/nested contradictory, or other negative status/outcome controls fail closed. Live fixture JSON uses the same discriminator and canonical payload rule; `content` and `output` are not report aliases. Its provenance schema `2.0` records `evidence_origin`, and formal result `2.0` records the matching origin for cross-binding into `promotion-method-m-v2`. Origin classifies the evidence as `runtime-observed` or `synthetic-contract`; it does not authorize promotion. The live decoder preflights depth and node ceilings before recursive JSON decoding, and a rejecting authoritative gate declaration remains rejecting even when it has a reason suffix or is followed by a PASS line.

Formal result `2.0` evaluates a standalone endpoint-checked target copy. It records that relative sibling context from the mutable source location is unavailable, binds the exact copy plus all required companions, and records package-tree, run, and target pre/post endpoint identities. Permission hardening does not prevent a same-UID A→B→A mutation between observations, so `temporal_immutability_enforced` is `false` and an otherwise `PASS-TRACKED` result is capped at `PASS-SCOPED`. Before `Popen`, capture must establish supported Linux `PR_SET_CHILD_SUBREAPER` plus `/proc` adopted-child tracking. It cleans the original process group and kills/reaps adopted detached-session descendants to a bounded quiet state, recording `linux-child-subreaper-plus-process-group`, `detached_descendant_survivor`, and `process_containment_cleanup_complete`. Unavailable containment refuses execution; a survivor or incomplete cleanup fails closed. The complete stream-json transcript is written before authentication and its full bytes determine parsing, byte count, and SHA-256; bounded public excerpts and truncation flags never replace the authenticated stream. A configured capture ceiling fails closed instead of discarding an early event or authenticating only a tail. Promotion finds this result only through its typed `formal.result` evidence role; basename substitution and glob-first selection are not trusted.

The formal output directory and compatibility JSON parent are each a held no-follow capability for the whole run. Their canonical-result-versus-compatibility-JSON classification is frozen during pre-execution collision analysis against held identities and is not recomputed after writing. Coordinator and gate children receive the runner-owned output directory's `/proc/<runner-pid>/fd/N` alias via `pass_fds`; parent and child writes use descriptor-relative exclusive creation, link/rename installation, and directory fsync. The runner reads the procfs-visible `Pid:` from `/proc/self/status`, while the gate admits only the exact canonical positive PID equal to its procfs-visible direct-parent `PPid:`. A child cannot redirect output by closing/rebinding FD `N`; self/unrelated PIDs, noncanonical or nonpositive PID/FD tokens, extra components, closed descriptors, and file descriptors are rejected. Replacing a lexical ancestor with a symlink or different real directory also cannot redirect output. Because this live path depends on POSIX `O_DIRECTORY`/`O_NOFOLLOW` and procfd inheritance, unsupported environments return `INVALID_INPUT` before creating the requested output directory or JSON file.

The same parent-capability rule applies before long-running work to live transcript/optional JSON output and to the gate, formal, regression, and promotion contract JSON wrappers. Live JSON may not alias a selected fixture transcript. Observed lexical-parent substitution fails closed without redirection, but endpoint and capability checks are not temporal isolation and do not exclude every same-UID mutation between observations.

Runtime identity is deliberately narrower than a software-supply-chain attestation: it binds the resolved executable entrypoint bytes used for the run, but not the transitive interpreter, shared-library, kernel, or host dependency closure.

## Required lane idea

The formal coordinator is expected to invoke the method cartographer, claim extractor, source verifier, code verifier, false-world adversary, true-world adherence reviewer, and gate auditor as native structured subagent lanes. Each lane must have a real call and a corresponding successful result.

## Event-boundary rule

Tool-like objects embedded inside payload data do not authenticate execution. The formal runner treats nested `tool_use` or `tool_result` objects under message content, data, payload, delta, or arguments as payload data, not as runtime events. Direction also matters when role context is available: assistant-origin tool-use and user-origin tool-result events are expected.

## Status cap

When trace authentication is missing or incomplete, a generated certificate may still be useful, but runtime status must be capped. The package should retain **PASS-SCOPED** or `UNVERIFIED_RUNTIME` rather than claiming PASS-TRACKED.

Generic `ntt_gate.py` semantics remain capable of `PASS-TRACKED` when their contract is satisfied. The v1.0.3 formal runner separately caps an otherwise `PASS-TRACKED` result at `PASS-SCOPED` while temporal immutability remains unenforced; process containment is a fail-before-execution prerequisite. The `certify_pass_tracked_upgrade.py` cap is additionally independent: even a complete modeled promotion is `PASS-SCOPED` / `CAPPED` with a nonzero exit until both Issue #5 charter obligations are mechanically implemented.

## Reviewer checklist

Rerun `run_formal_runner_contract_tests.py` to an external JSON path and review its cases covering fake traces, nested event smuggling, role inversion, duplicate tool-use IDs, missing results, generic results, text-only masquerades, unexpected agent calls, an early general-purpose event followed by a large valid-looking tail, complete transcript binding, resource limits, normal-exit original-group cleanup, Linux detached-session adoption/kill/reap, fail-before-execution when containment is unavailable, temporal-immutability capping, pre-acquired live transcript/JSON and wrapper output capabilities, frozen formal JSON classification, output aliases, and ancestor substitution.
